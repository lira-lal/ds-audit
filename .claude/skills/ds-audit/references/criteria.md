# 판정 기준

## 임시 조건 — 무료 플랜

한 파일 안에서 테스트 중이다. 유료 전환 시 이 절만 삭제한다.

- 퍼블리시/로컬 구분은 하지 않는다
- 같은 파일 라이브러리 페이지의 컴포넌트를 라이브러리로 간주한다
- 시안 페이지에서 직접 그린 프레임을 위반 후보로 본다
- components.md 상태 칸이 비어 있는 컴포넌트에 한해, 이름 프리픽스(`_deprecated/`, `_wip/`)를 상태의 보조 신호로 쓴다. 프리픽스는 근거가 아니라 힌트이며, 상태 칸이 채워져 있으면 언제나 상태 칸이 우선이다. 프리픽스도 상태 칸도 없으면 상태를 추정하지 말고 "확정"으로 본다

---

## 판정 순서

위에서부터 확인하고, 맞는 항목이 나오면 멈춘다.

```
1. exceptions.md 에 있나
   → 예: 예외 승인. 종료

2. 라이브러리 컴포넌트의 인스턴스인가
   → 아니오: 5번으로

3. components.md 의 상태가 "확정"인가
   → 없어질 예정(대체 컴포넌트가 지정돼 있음): 없어질 컴포넌트를 씀 · 보통
   → 확정 대기: 확정 대기 · 경미
   → 확정: 4번으로
   ※ 상태는 components.md 상태 칸에서 읽는다. 레이어 이름으로 상태를 판단하지 않는다
     (상태 칸이 비었을 때의 예외는 위 "임시 조건" 절 참조)

4. 값을 고쳤나
   → 아니오: 문제 없음
   → 예: 바뀐 값이 변수에 연결됐는지(bound)를 먼저 확인하고 심각도는 아래 표로 정한다
      - 변수 연결 없이 값을 직접 입력함 (bound:false) → 값 직접 입력 · 심각도는 아래 표
      - 다른 등록된 변수로 교체함 (bound:true, 원본과 다른 변수) → 변수 교체 · 심각도는 아래 표 (한 단계 낮음)

5. components.md 에 유사품이 있나 (근거 2개 이상)
   → 예: 있는 걸 직접 그림 · 보통
   → 아니오: 없는 걸 직접 그림 · 경미

6. (5번 분기 전용) 직접 그린 요소 자신의 색·모서리 등이 변수 연결 없이 값을 직접 입력됐나
   → 예: 값 직접 입력 · 심각  (5번과 중복 표기 가능)
```

예외 확인을 맨 앞에 둔다. 뒤로 미루면 승인된 예외가 매번 지적되어 출력이 노이즈로 덮인다.

## 변경 허용 범위

| 고친 부분 | 판정 |
|---|---|
| 글자 내용 | 허용 |
| 변형 전환 | 허용 |
| 인스턴스 교체 (아이콘 등) | 허용 |
| 크기 — 자동 (채움·감쌈) | 허용 |
| 크기 — 고정값 직접 변경 | 보통 |
| 안쪽 여백 · 요소 간격 | 보통 |
| 색 · 글꼴 · 모서리 — 변수 연결 없이 값 직접 입력 (bound:false) | 심각 |
| 색 · 글꼴 · 모서리 — 다른 등록된 변수로 교체 (bound:true, 다른 변수) | 보통 |

## 유사품 판정

대조 근거 4가지. **2개 이상 일치할 때만** 유사품으로 올린다. 1개 이하면 "없는 걸 직접 그림"으로 보낸다.

| 근거 | 확인 방법 |
|---|---|
| 이름 | 레이어명 ↔ 컴포넌트명 유사어 |
| 구조 | 자식 요소 구성 일치 |
| 치수 | 높이·모서리·여백 근사 |
| 용도 | components.md 의 용도 필드 ↔ 요소가 놓인 위치 |

용도가 판정의 중심이다. 나머지 셋은 겉모습이라 우연히 일치할 수 있다.

추론이므로 신뢰도가 낮다. 두 가지를 반드시 지킨다.

- 차이점 칸을 채운다. 비어 있으면 그 판정은 무효
- 액션은 "교체 검토"까지. "교체하세요"라고 쓰지 않는다

## 위반 유형

심각도와는 다른 축이다. 심각도는 얼마나 급한가이고, 유형은 어느 영역이 어긋났는가다.
어긋난 속성이 무엇인지로 기계적으로 정해지므로 추론하지 않는다.

| 유형 | 어긋난 속성 |
|---|---|
| 컬러 | fills · strokes |
| 모서리 | cornerRadius |
| 간격 | itemSpacing · paddingLeft/Right/Top/Bottom |
| 크기 | width · height (고정값일 때만) |
| 타이포 | 텍스트 스타일 |
| 컴포넌트 | 인스턴스가 아님 · 상태가 확정이 아님 |

한 요소가 여러 영역에서 동시에 어긋나면 전부 적는다. 순서는 위 표 순서를 따르되,
컴포넌트가 걸려 있으면 그것을 맨 앞에 둔다 — 자동 수정 가능 여부를 가르는 유형이기 때문이다.

## 심각도

| 값 | 뜻 |
|---|---|
| 심각 | 시스템 원칙을 깬 것. 반드시 수정 |
| 보통 | 고쳐야 하나 급하지 않음 |
| 경미 | 기록만 |

## 출력 형식

`output/{YYYY-MM-DD}_{프레임명}.md`

```
| 요소명 | 위치 | 유형 | 출처 | 결과 | 유사 기존 | 차이점 | 액션 | 심각도 |
|---|---|---|---|---|---|---|---|---|
```

**같은 노드(요소)는 행을 하나만 낸다.** 값 직접 입력·크기 고정값 변경·layoutPositioning 오버라이드처럼 한 요소에서 여러 판정 기준에 동시에 걸려도 행을 나누지 않고 한 행으로 합친다 — 심각도는 그중 가장 높은 것을 쓰고, 결과·차이점 칸에 해당하는 사유를 전부 나열한다 (예: "값 직접 입력 + 크기 고정값 변경"). 같은 이름의 인스턴스가 여러 개 있어 서로 다른 노드일 때만 별도 행으로 낸다.

| 칸 | 내용 |
|---|---|
| 요소명 | 레이어명 |
| 유형 | 어느 영역이 어긋났나 — 컬러 / 모서리 / 간격 / 크기 / 타이포 / 컴포넌트. 한 요소가 여럿에 걸리면 전부 적는다 |
| 위치 | 프레임 내 대략 위치 (상단·하단·리스트 등) |
| 출처 | 라이브러리 / 직접 그림 / — |
| 결과 | 판정 순서의 결과 문구 그대로 |
| 유사 기존 | 5번(유사품 판정) 결과에만 채운다 — 컴포넌트명 또는 "없음". 4번(인스턴스 값 변경) 판정에는 원본이 이미 그 컴포넌트 자신이므로 "—" |
| 차이점 | 유사품 판정 시 필수. 값 변경 판정(4번)에서는 바뀐 속성과 bound 여부(변수 연결 없음/다른 변수로 교체)를 적는다 |
| 액션 | 원복 검토 / 교체 검토 / 등재 검토 / 육안 확인 / — |
| 심각도 | 심각 / 보통 / 경미 / — |

표 아래 요약 한 줄

```
문제없음 n / 심각 n / 보통 n / 경미 n / 예외 n / 확인불가 n
```

이어서 갱신 제안 표. 없으면 "제안 없음".

```
| 대상 파일 | 제안 | 상태 |
|---|---|---|
```

상태는 항상 "승인 대기"로 쓴다.
