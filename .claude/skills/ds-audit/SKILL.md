# 디자인 시스템 대조

## 실행 순서

1. `data/` 전체를 읽는다 — components.md, exceptions.md, naming.md
2. Figma MCP로 대상 프레임의 노드 트리와 변수 컬렉션을 조회한다
3. 판정 대상 요소만 추려 리스트로 만든다 (평탄화 규칙 아래 참조)
4. `references/criteria.md` 순서대로 판정한다
5. `output/{YYYY-MM-DD}_{프레임명}.md` 에 표를 쓴다
6. 갱신이 필요하면 제안 표만 출력한다. `data/` 를 직접 수정하지 않는다

`data/components.md` 의 목록이 비어 있거나 용도 칸이 전부 비어 있으면 판정을 시작하지 말고 먼저 알린다.

## 평탄화

인스턴스에서 하위 탐색을 멈추고 변경된 값 목록만 별도로 수집한다.

판정 대상 — 인스턴스, 컴포넌트처럼 보이는 프레임·그룹, 스타일 값을 가진 도형
판정 제외 — 순수 레이아웃 프레임, 마스크·가이드. 텍스트 노드는 변수·스타일 연결만 확인

## 금지

- 근거 없는 추측 금지. 모르면 "확인 불가"로 표기한다
- components.md 에 없는 컴포넌트를 있다고 추정하지 않는다
- 유사도를 단정하지 않는다. 차이점 칸이 비면 그 판정은 무효다
- 구조 데이터를 읽지 못한 요소는 분류를 배정하지 않는다
- exceptions.md 항목을 출력에서 빼지 않는다. "예외 승인"으로 표기만 한다
- 예외를 임의로 승인하지 않는다. 전부 표에 올리고 사람이 판단한다
- `data/` 파일을 자동 수정하지 않는다
- 디자인 의도·미감을 평가하지 않는다
- 표 앞뒤에 설명을 붙이지 않는다

## 출력

`references/criteria.md` 의 표 형식을 그대로 쓴다. 표와 요약 한 줄, 갱신 제안까지만.

## 목록 추출 모드

"컴포넌트 목록 뽑아줘" 요청 시 — 라이브러리 페이지를 조회해 아래 표를 출력한다. 없는 컴포넌트나 변형을 만들어내지 않는다.

| 컴포넌트명 | 용도 | 변형 | 상태 | 대체 컴포넌트 | 구분 기준 |
|---|---|---|---|---|---|

용도 초안을 요청받으면 구조·치수·자식 요소를 근거로 제안하되, 추론이라는 점을 명시하고 확실하지 않으면 "확인 필요"로 둔다. 초안을 확정된 사실로 쓰지 않는다.
