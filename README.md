# DS Audit

피그마 시안이 디자인 시스템을 따르는지 대조해서, 어긋난 요소를 심각도와 함께 짚어주는 검수 도구.

**Figma 플러그인**으로 쓰거나, **Claude Code 스킬**로 터미널에서 쓸 수 있다. 둘 다 같은 판정 기준(`criteria.md`)과 같은 컴포넌트 목록(`data/`)을 근거로 판정한다.

<br>

## 어떻게 동작하나

```
┌─────────────────────────┐
│  Figma 플러그인          │  프레임 선택 → 노드 트리에서
│  (plugin/)              │  구조 신호만 추출 (판정 안 함)
└───────────┬─────────────┘
            │  POST http://localhost:8787/judge
            ▼
┌─────────────────────────┐
│  릴레이 서버             │  claude -p --output-format json
│  (relay-server/)        │  --tools '' --model <선택한 모델>
└───────────┬─────────────┘
            │
            ▼
      Claude Code CLI  ←── 이미 로그인된 구독 사용
            │
            ▼  판정 결과 JSON
┌─────────────────────────┐
│  플러그인 UI             │  심각도별 표시 · 해당 노드로 포커스
└───────────┬─────────────┘
            │  모델이 만든 판정 + 플러그인이 계산한 수정 계획
            ▼
┌─────────────────────────┐
│  자동 수정               │  값이 등록 변수와 맞아떨어지는 건만
│  (autofix.ts)           │  변수 연결로 바꾼다
└─────────────────────────┘
```

**API 키가 필요 없다.** Anthropic API를 직접 부르지 않고, 로컬 릴레이 서버가 이미 로그인된 Claude Code CLI를 실행한다. 그래서 별도 키 발급 없이 기존 구독 사용량으로 처리된다.

시안 데이터는 로컬 릴레이 서버(`localhost:8787`)만 거친다. 플러그인 매니페스트의 `networkAccess.allowedDomains` 는 `none` 이라 외부로 나가는 경로가 없다.

## Figma 플러그인으로 쓰기

### 1. 데이터 파일 채우기

빌드 시 `data/` 와 `criteria.md` 내용이 시스템 프롬프트로 구워지므로(`npm run bake`), **빌드 전에 먼저 채운다.**

`data/components.md` 의 변수 표가 비어 있다. Claude Code에서:

```
라이브러리 변수 목록 뽑아줘
https://figma.com/design/{라이브러리 링크}
```

나온 표를 `data/components.md` 의 변수 절에 붙인다.

### 2. 플러그인 빌드

```bash
cd plugin
npm install
npm run build
```

`npm run build` 는 두 단계다.

| 단계 | 하는 일 |
|---|---|
| `npm run bake` | `criteria.md` + `data/*.md` → `src/promptData.generated.ts` 로 시스템 프롬프트 생성 |
| `build-figma-plugin` | `manifest.json` 과 `build/main.js`, `build/ui.js` 생성 |

`manifest.json` 과 `promptData.generated.ts` 는 빌드 산출물이라 git에 없다. **빌드를 돌려야 생긴다.**

개발 중에는 `npm run watch` 로 자동 재빌드.

### 3. Figma에 불러오기

Figma **데스크톱 앱**에서 (브라우저는 개발 플러그인 로드가 안 된다):

```
Plugins → Development → Import plugin from manifest…
→ plugin/manifest.json 선택
```

### 4. 릴레이 서버 켜기

검수를 돌리기 전에 별도 터미널에서 띄워둔다. 이게 안 켜져 있으면 플러그인이 판정을 못 한다.

```bash
cd relay-server
npm start          # localhost:8787
```

Claude CLI가 로그인돼 있어야 한다. 플러그인 UI의 **연결 테스트** 버튼이 `/health` 로 `claude auth status` 를 확인해준다.

### 5. 검수

1. 캔버스에서 검수할 프레임을 선택한다 (여러 개 선택 가능)
2. 플러그인에서 모델을 고른다 — **Opus 5**(권장, 판단력) 또는 **Sonnet 5**(비용 절감)
3. **검수 시작** 실행

## 플러그인 기능

| 기능 | 설명 |
|---|---|
| **선택 연동** | 캔버스 선택이 바뀌면 플러그인이 대상을 자동으로 따라간다 |
| **여러 프레임 일괄 검수** | 선택한 프레임을 순서대로 처리하고, 진행 상황을 프레임 단위로 알린다 |
| **심각도별 결과** | 심각 · 보통 · 경미 · 문제없음 으로 묶고, 요약 카운트를 상단에 고정 |
| **위반 유형 구분** | 컬러 · 모서리 · 간격 · 크기 · 타이포 · 컴포넌트 여섯으로 나눠 아이콘으로 표시 |
| **프레임별 탭** | 프레임이 둘 이상이면 탭으로 나누고 건수 배지를 단다 |
| **노드 포커스** | 결과의 컴포넌트명을 누르면 캔버스의 해당 요소로 이동 (다른 페이지면 페이지까지 전환) |
| **자동 수정** | 값이 등록 변수와 맞아떨어지는 건을 변수 연결로 바꾼다. 개별·일괄 모두 가능하고 `Cmd+Z` 로 되돌아간다 |
| **모델 저장** | 마지막에 고른 모델을 `figma.clientStorage` 에 저장해 다음 실행에 이어 쓴다 |

화면은 **검수 준비 · 설정 · 검수 결과** 세 개다. 설정에서는 모델을 고르고 릴레이 서버 연결을 테스트한다.

프레임이 크면 요소 200개까지만 추출하고 나머지는 건너뛴다 (건너뛴 경우 Figma 알림으로 알려준다).

## 판정 기준

`.claude/skills/ds-audit/references/criteria.md` 가 유일한 기준 문서다. 플러그인과 스킬이 같은 파일을 쓴다.

### 판정 순서

위에서부터 확인하고, 맞는 항목이 나오면 멈춘다.

| # | 확인 | 판정 |
|---|---|---|
| 1 | `exceptions.md` 에 있나 | 예외 승인 · 종료 |
| 2 | 라이브러리 컴포넌트의 인스턴스인가 | 아니오 → 5번으로 |
| 3 | `components.md` 의 상태가 "확정"인가 | 없어질 예정 · **보통** / 확정 대기 · **경미** |
| 4 | 값을 고쳤나 | 안 고쳤으면 문제 없음. 고쳤으면 변수 연결 여부로 심각도 결정 (아래 표) |
| 5 | `components.md` 에 유사품이 있나 (근거 2개 이상) | 있으면 있는 걸 직접 그림 · **보통** / 없으면 없는 걸 직접 그림 · **경미** |
| 6 | 직접 그린 요소가 변수 없이 값을 직접 입력했나 | 값 직접 입력 · **심각** |

예외 확인을 맨 앞에 둔다. 뒤로 미루면 승인된 예외가 매번 지적되어 출력이 노이즈로 덮인다.

각 단계는 원칙만 담는다. "어떤 컴포넌트가 어떤 상태인가" 같은 사실은 `components.md` 의 상태 칸에서 읽고, 판정 기준에 적지 않는다. 레이어 이름으로 상태를 판단하지 않는다 — 이름 규칙은 `naming.md` 소관이고, 상태 칸이 비었을 때만 보조 신호로 쓴다.

### 위반 유형

심각도와는 다른 축이다. 심각도는 얼마나 급한가이고, 유형은 어느 영역이 어긋났는가다. 어긋난 속성이 무엇인지로 기계적으로 정해지므로 추론하지 않는다.

| 유형 | 어긋난 속성 |
|---|---|
| 컬러 | `fills` · `strokes` |
| 모서리 | `cornerRadius` |
| 간격 | `itemSpacing` · `paddingLeft/Right/Top/Bottom` |
| 크기 | `width` · `height` (고정값일 때만) |
| 타이포 | 텍스트 스타일 |
| 컴포넌트 | 인스턴스가 아님 · 상태가 확정이 아님 |

한 요소가 여러 영역에서 동시에 어긋나면 전부 적는다. 컴포넌트가 걸려 있으면 맨 앞에 둔다 — 자동 수정 가능 여부를 가르는 유형이기 때문이다.

### 변경 허용 범위

인스턴스에서 무엇을 고쳤을 때 어디까지 봐주는지.

| 고친 부분 | 판정 |
|---|---|
| 글자 내용 | 허용 |
| 변형 전환 | 허용 |
| 인스턴스 교체 (아이콘 등) | 허용 |
| 크기 — 자동 (채움·감쌈) | 허용 |
| 크기 — 고정값 직접 변경 | 보통 |
| 안쪽 여백 · 요소 간격 | 보통 |
| 색 · 글꼴 · 모서리 — 변수 연결 없이 값 직접 입력 | **심각** |
| 색 · 글꼴 · 모서리 — 다른 등록된 변수로 교체 | 보통 |

### 유사품 판정

직접 그린 요소가 기존 컴포넌트와 겹치는지 볼 때, 대조 근거 4가지 중 **2개 이상 일치할 때만** 유사품으로 올린다.

| 근거 | 확인 방법 |
|---|---|
| 이름 | 레이어명 ↔ 컴포넌트명 유사어 |
| 구조 | 자식 요소 구성 일치 |
| 치수 | 높이·모서리·여백 근사 |
| 용도 | `components.md` 의 용도 필드 ↔ 요소가 놓인 위치 |

용도가 판정의 중심이다. 나머지 셋은 겉모습이라 우연히 일치할 수 있다. 추론이라 신뢰도가 낮으므로 차이점 칸이 비면 그 판정은 무효로 되돌리고, 액션은 "교체 검토"까지만 쓴다.

### 심각도

| 값 | 뜻 |
|---|---|
| 심각 | 시스템 원칙을 깬 것. 반드시 수정 |
| 보통 | 고쳐야 하나 급하지 않음 |
| 경미 | 기록만 |
| 예외 | `exceptions.md` 에 등록되어 승인된 항목 |
| 확인불가 | 구조 데이터를 읽지 못해 판정할 수 없음 |

오탐이 나오면 `criteria.md` 를 고치고 **`npm run bake` 를 다시 돌린다.** 프롬프트가 빌드 시점에 구워지기 때문에, 기준만 고치고 재빌드하지 않으면 플러그인 동작은 그대로다. `SKILL.md` 는 실행 순서만 담고 있어 자주 손대지 않는다.

## 자동 수정

### 무엇을 고칠지는 모델에게 묻지 않는다

모델은 **판정만** 한다 — 어긋났는지, 어느 유형인지, 얼마나 심각한지, 그리고 왜 그런지를 문장으로 쓴다.

무엇을 어떻게 고칠지는 플러그인이 `autofix.ts` 에서 직접 계산한다. **모델이 `nodeId` 를 지어내면 엉뚱한 노드를 건드리게 되기 때문이다.** 모델은 입력 데이터에 있던 `nodeId` 를 그대로 옮기기만 하고, 플러그인이 그 노드를 구조 데이터에서 다시 찾아 등록된 변수와 실제 값을 대조한다. 대조에 실패하면 고치지 않는다.

| 채우는 주체 | 필드 |
|---|---|
| 모델 | `요소명` `nodeId` `유형` `심각도` `결과` `차이점` `액션` |
| 플러그인 | `fixes` (수정 계획) `blocked` (막힌 항목과 사유) |

### 고치는 조건

| 유형 | 조건 | 동작 |
|---|---|---|
| 컬러 | `fills` · `strokes` 값이 등록 변수와 **정확히** 같을 때 | 해당 변수에 연결 |
| 모서리 | `cornerRadius` 가 `radius/*` 와 **차이 2 이내** | 가장 가까운 변수에 연결 |
| 간격 | `padding*` · `itemSpacing` 이 `Padding/*` · `Space/*` 와 **차이 2 이내** | 해당 변수에 연결 |

차이 2를 넘기면 손대지 않는다. 그보다 멀면 의도한 다른 값일 수 있다. 수정은 추측이 아니라 사실이어야 한다.

### 고치지 않는 것

| 상황 | 남기는 사유 |
|---|---|
| 직접 그린 프레임 · 도형 | `인스턴스로 바꾸면 안의 내용이 사라집니다` |
| 값에 맞는 등록 변수가 없음 | `값과 맞아떨어지는 등록 변수가 없습니다` |
| 구조 데이터에서 노드를 못 찾음 | `구조 데이터에서 해당 노드를 찾지 못했습니다` |

크기(`width` · `height`) 고정값은 되돌리면 레이아웃이 밀릴 수 있어 보류한다.

### 수정 후에는 재검수하지 않는다

고친 항목은 추론이 아니라 **사실**이다. 플러그인이 변수를 실제로 연결했으므로 다시 물어볼 이유가 없다. 고친 건을 목록에서 덜어내고 요약만 다시 센다. `Cmd+Z` 로 되돌아간다.

## Claude Code 스킬로 쓰기

플러그인 없이 터미널에서 쓰는 방식. 결과는 `output/` 에 마크다운으로 저장된다.

### 실행

```bash
cd ~/NewRoot/Docs/원티드_ai네이티브/ds
claude
```

`.claude/` 가 있는 폴더에서 실행해야 스킬이 인식된다. `/mcp` 에 Figma가 있어야 검수가 된다.

### 검수

```
이 프레임 검수해줘
https://figma.com/design/{프레임 링크}
```

판정 기준·출력 형식·저장 위치는 `SKILL.md` 에 있으므로 매번 말하지 않는다.

스킬 쪽에는 자동 수정이 없다. 고치는 일은 플러그인에서 한다.

<br>

아래는 판정이 의도대로 나오는지 확인하려고 **직접 만들어 둔 샘플 프레임 목록**이다. 도구가 검수하는 범위가 아니다 — 검수 범위는 위의 판정 순서와 `criteria.md` 가 전부다.

| 테스트 프레임 | 기대 결과 |
|---|---|
| 컴포넌트 | 문제 없음 |
| 인스턴스/컬러변경 | 컴포넌트 값을 임의로 고침 · 심각 |
| 인스턴스/디테치 | 있는 걸 직접 그림 · 보통 |
| 인스턴스/디테치/컬러변경 | 있는 걸 직접 그림 + 값 직접 입력 · 심각 |

프레임별로 각각 검수를 돌린다.

**아직 안 만든 테스트 프레임**

판정 기준에는 있지만 확인용 샘플을 아직 안 만든 케이스.

| 판정 항목 | 만들 프레임 |
|---|---|
| 크기 — 고정값 직접 변경 · 보통 | 인스턴스 하나의 높이만 고정값으로 변경 |
| 없는 걸 직접 그림 · 경미 | 아무것과도 안 닮은 도형 하나 |
| 없어질 컴포넌트 · 보통 | `components.md` 상태를 "없어질 예정"으로 바꾸고 대체 컴포넌트를 지정한 뒤, 그 인스턴스를 배치 |
| 확정 대기 · 경미 | `components.md` 상태를 "확정 대기"로 바꾼 컴포넌트의 인스턴스를 배치 |
| **유사품 판정 (어려운 케이스)** | 사각형 + 제목 + 캡션을 직접 그리고 레이어명을 `아이템` 으로 지정 |

마지막 항목이 가장 중요하다. 디테치 케이스는 레이어명이 그대로 남아 근거 3개가 일치하므로 쉬운 문제다. 실제 중복 제작은 처음부터 다르게 그릴 때 생긴다.

## 안 될 때

### 플러그인

| 증상 | 원인 |
|---|---|
| Figma 플러그인 목록에 없음 | `npm run build` 안 돌려서 `manifest.json` 이 없음 |
| Import 메뉴가 안 보임 | 브라우저에서 열었음 — 데스크톱 앱이어야 한다 |
| 연결 실패 / 검수 무반응 | 릴레이 서버가 안 켜져 있음 (`cd relay-server && npm start`) |
| 연결 테스트에서 로그인 실패 | Claude CLI 미로그인 — `claude auth status` 확인 |
| 기준을 고쳤는데 결과가 그대로 | `npm run bake` 재실행 안 함 (프롬프트는 빌드 시점에 구워진다) |
| 응답 파싱 실패 | 모델이 JSON 앞뒤에 설명을 붙임 — 재시도하거나 모델 변경 |
| 큰 프레임에서 일부 요소 누락 | 요소 200개 상한 |
| 자동 수정 버튼이 안 눌림 | 고칠 수 없는 건이다. 카드에 사유가 함께 나온다 (직접 그린 요소 / 맞는 변수 없음) |
| 자동 수정했는데 값이 그대로 | 값이 등록 변수와 차이 2를 넘음 — 변수를 추가하거나 직접 맞춘다 |

### 스킬

| 증상 | 원인 |
|---|---|
| 스킬을 안 씀 | `.claude/` 가 없는 폴더에서 실행함 |
| 피그마를 못 읽음 | `/mcp` 에 Figma 없음 |
| 목록이 비었다고 함 | `data/components.md` 경로 확인 |

### 판정 품질

| 증상 | 원인 |
|---|---|
| 전부 "직접 그림"으로 나옴 | 인스턴스로 배치했는지 확인 |
| 유사품을 못 찾음 | 용도 필드가 부실함 |
| 엉뚱한 것을 유사품으로 잡음 | 구분 기준 칸 보강 |
| 컨테이너·텍스트까지 지적됨 | `SKILL.md` 평탄화 규칙 확인 |
